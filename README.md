# Блок 8. Мини-помощник по учебным документам (RAG / TF-IDF)

Консольное приложение по мотивам ноутбука `Block08_RAG_Text_TODO`.
Помощник принимает вопрос своими словами, находит подтверждающий
документ и отвечает точными цитатами с указанием источника. Если
подтверждения нет, он честно сообщает об этом и не выдумывает факт.

## 1. Цель проекта

Показать обязательную поисковую часть RAG без обучения большой
языковой модели:

1. разбить документы на чанки;
2. построить TF-IDF индекс;
3. найти ближайшие фрагменты по вопросу;
4. выдать точные предложения-цитаты с номерами источников;
5. сравнить настройки поиска по метрикам Top-1 и Hit@K;
6. проверить случай, когда ответа в документах нет.

## 2. Датасет и база знаний

Учебная вымышленная база знаний из ноутбука блока 8. Она не является
официальным регламентом организации.

- `data/documents.json` — 17 документов: `D01`–`D16` из ноутбука и
  собственный документ `STUDENT`;
- `data/check_questions.json` — 33 контрольных вопроса: 32 из ноутбука
  и 1 свой вопрос к документу `STUDENT`;
- `notebooks/Block08_RAG_Console_SOLVED.ipynb` — решённый ноутбук,
  который использует те же модули и повторяет все шаги экзамена.

Схема данных: [docs/data_description.md](docs/data_description.md).

## 3. Изменённые параметры

Относительно исходного ноутбука изменены **четыре** параметра:

| Параметр | Значение | Комментарий |
|---|---:|---|
| `CHUNK_SIZE` | **230** | короче исходного 650, точнее нацеливает поиск |
| `OVERLAP` | **30** | меньше исходного 110, меньше дублирования |
| `SEARCH_METHOD` | **`char_wb`** | поиск по группам букв устойчивее к окончаниям |
| `TOP_K` | **3** | до трёх разных источников на ответ |

При этих настройках получилось **47 чанков**. На 33 контрольных вопросах
базовый вариант дал **Top-1 = 1.000** и **Hit@K = 1.000**.

## 4. Пять экспериментов

| Код | Чанк | Overlap | Поиск | Top-K | Чанков | Top-1 | Hit@K |
|---|---:|---:|---|---:|---:|---:|---:|
| A: слова / 1 источник | 380 | 45 | word | 1 | 33 | 0.909 | 0.909 |
| B: буквы / 2 источника | 380 | 45 | char_wb | 2 | 33 | 0.970 | 1.000 |
| C: короткие чанки | 200 | 30 | char_wb | 3 | 52 | **1.000** | **1.000** |
| D: длинные чанки | 700 | 100 | char_wb | 3 | 17 | 0.970 | 1.000 |
| **E: слова / без перекрытия / 5 источников** | 300 | 0 | word | 5 | 35 | 0.909 | 0.939 |

### Объяснение по графикам и таблице

- **A против B.** При одинаковых чанках поиск по группам букв
  (`char_wb`) дал Top-1 0.970 против 0.909 у поиска по словам. Это
  ожидаемо: разные окончания русского слова меньше мешают.
- **B против A по Top-K.** У B `top_k=2`, поэтому Hit@K = 1.000: даже
  если верный документ не первый, он попадает в выдачу.
- **C против D.** Короткие чанки (200) дали Top-1 1.000, длинные (700) —
  0.970. Короткий чанк ближе к одному предложению-ответу, а длинный
  содержит лишние слова и размывает сходство.
- **Новый опыт E.** Здесь изменены сразу три вещи: поиск по словам,
  `overlap=0`, `top_k=5`. Top-1 = 0.909, Hit@K = 0.939. Большое Top-K
  повышает шанс найти верный источник, но добавляет шум; отсутствие
  перекрытия уменьшает число чанков (35), но может разорвать мысль на
  границе. Word-поиск слабее `char_wb` на русских словоформах.

Графики: `reports/charts/experiments_metrics.png` (Top-1 и Hit@K) и
`reports/charts/chunks_per_experiment.png` (число чанков).

## 6. Случай без подтверждённого ответа

**Посторонний вопрос:** «Сколько студенту нужно отжаться на брусьях?»

Лучший найденный фрагмент имел сходство всего 0.109. При пороге 0.20

> Не нашёл подтверждённого ответа в учебных документах.

Файл: `reports/no_answer.txt`. Это важное правило ответственного ИИ:
лучше признать отсутствие данных, чем выдать случайный фрагмент за ответ.

## 7. TF-IDF, нейросетевой поиск и полноценный RAG с LLM

| Подход | Что делает | Глубокое обучение | Ограничение |
|---|---|---|---|
| **TF-IDF** | Считает статистическую важность слов / групп символов и сравнивает векторы | Нет | Не понимает синонимы без общих слов |
| **Семантический поиск** | Сравнивает эмбеддинги предобученной нейросети | Да, готовая модель | Требует ресурсов и тоже ошибается |
| **RAG с LLM** | Поиск + передача фрагментов языковой модели, которая пишет новый ответ | Да | LLM может галлюцинировать; нужна проверка по источникам |

Наш помощник реализует **Retrieval** и показывает точные выдержки из
источников. Пока не подключена языковая модель, это **не генерация**.
В факультативных режимах можно:

- `--neural` — сравнить нейросетевой поиск `sentence-transformers`
  с TF-IDF;
- `--llm` — сгенерировать ответ локальной моделью `Qwen2.5-0.5B-Instruct`
  и проверить, не придумала ли она факты.

Оба режима требуют интернета и установки дополнительных пакетов; на
обычном запуске они выключены, чтобы обязательная часть работала без сети.

## 8. Архитектура

| Модуль | Назначение |
|---|---|
| `src/config.py` | пути, параметры, пороги, пять экспериментов |
| `src/data_loader.py` | загрузка JSON и сохранение CSV/JSON/TXT |
| `src/chunker.py` | разбиение документов на чанки с перекрытием |
| `src/retriever.py` | TF-IDF индекс и поиск разных документов |
| `src/answerer.py` | ответ цитатами с источниками и отказ при слабом сходстве |
| `src/evaluator.py` | Top-1 и Hit@K на контрольных вопросах |
| `src/experiments.py` | перебор настроек и сбор таблицы результатов |
| `src/assistant.py` | высокоуровневый помощник для консоли |
| `src/visualizer.py` | сохранение графиков |
| `src/report_builder.py` | итоговый markdown-отчёт |
| `src/neural_retriever.py` | факультативный семантический поиск |
| `src/llm_generator.py` | факультативная генерация локальной LLM |
| `main.py` | единый сценарий запуска |

## 9. Как запустить

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python main.py
python -m pytest -q
```

Режимы приложения:

```bash
python main.py --ask
python main.py --question "Что показывает precision?"
python main.py --neural
python main.py --llm
```

После полного запуска появляются:

- `reports/experiments.csv` — таблица пяти опытов;
- `reports/retrieval_check.csv` — проверка каждого контрольного вопроса;
- `reports/settings.json` — параметры запуска;
- `reports/demo_answer.txt`, `reports/custom_answer.txt`,
  `reports/no_answer.txt` — примеры ответов;
- `reports/charts/*.png` — графики;
- `reports/final_report.md` — итоговый отчёт;
- `notebooks/Block08_RAG_Console_SOLVED.ipynb` — решённый ноутбук.

## 10. Ограничения

- база знаний маленькая и учебная (17 документов);
- TF-IDF не понимает синонимы без общих слов;
- ответ собирается из цитат, а не генерируется LLM;
- порог сходства нужно настраивать на своих вопросах;
- найденная цитата не заменяет проверку прав доступа и содержания;
- семантический поиск и LLM — факультатив и требуют ресурсов.
