# Блок 8. Мини-помощник по учебным документам (RAG / TF-IDF)

Консольное приложение по мотивам ноутбука `Block08_RAG_Text_TODO`.
Система ищет ответ в локальной базе знаний, показывает подтверждающие
цитаты и честно сообщает, если подтверждённого ответа нет.

## 1. Цель проекта

Задать вопрос своими словами, найти подтверждающий документ и получить
ответ с указанием источника. Обязательная часть использует **TF-IDF** —
статистический поиск без обучения глубокой нейросети. Это поисковая
часть RAG, а не генерация текста языковой моделью.

## 4. Пять экспериментов

| опыт | чанк | overlap | поиск | top_k | чанков | top1 | hit_at_k |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A: слова / 1 источник | 380 | 45 | word | 1 | 33 | 0.909 | 0.909 |
| B: буквы / 2 источника | 380 | 45 | char_wb | 2 | 33 | 0.97 | 1.0 |
| C: короткие чанки | 200 | 30 | char_wb | 3 | 52 | 1.0 | 1.0 |
| D: длинные чанки | 700 | 100 | char_wb | 3 | 17 | 0.97 | 1.0 |
| E: слова / без перекрытия / 5 источников | 300 | 0 | word | 5 | 35 | 0.909 | 0.939 |

### Что видно по таблице и графикам

1. Лучший Top-1 у варианта «C: короткие чанки»: 1.000. Лучший Hit@K у «B: буквы / 2 источника»: 1.000.
2. A и B отличаются способом поиска при одинаковых чанках: word даёт Top-1 0.909 / Hit@K 0.909, char_wb — 0.970 / 1.000. Поиск по группам букв устойчивее к окончаниям, а Top-K добавляет второй шанс найти верный документ.
3. C и D показывают влияние размера чанка: короткие чанки (200 символов) дают Top-1 1.000, длинные (700 символов) — 0.970. Короткие чанки точнее нацелены на предложение-ответ, но могут терять контекст; длинные сохраняют контекст, но размывают сходство.
4. Новый эксперимент E меняет сразу способ поиска, overlap и Top-K: word, overlap=0, top_k=5. Он даёт Top-1 0.909 и Hit@K 0.939. Большое Top-K повышает шанс найти нужный источник, но добавляет шум в выдачу; overlap=0 уменьшает число чанков и может разрывать мысль на границе.

## 6. Случай, когда подтверждённого ответа нет

**Посторонний вопрос:** Сколько студенту нужно отжаться на брусьях?

**Лучший найденный источник:** D12 — RAG: чанки и параметры (сходство 0.109)

**Ответ системы:**

```text
Не нашёл подтверждённого ответа в учебных документах.
```

Порог сходства для этого примера поднят до
`0.2`. Поиск всё равно возвращает
какой-то фрагмент, но система не выдаёт его за подтверждённый ответ.
Это важное правило ответственного ИИ: лучше сказать «нет данных»,
чем выдумать факт.

## 7. TF-IDF, нейросетевой поиск и полноценный RAG с LLM

| Подход | Что делает | Глубокое обучение? | Ограничение |
|---|---|---|---|
| **TF-IDF** | Сравнивает слова / группы символов и их статистическую важность | Нет | Не понимает синонимы и смысл без общих слов |
| **Семантический поиск** | Сравнивает эмбеддинги предобученной нейросети | Да, используется готовая модель | Может ошибаться и требует ресурсов |
| **RAG с LLM** | Поиск + передача фрагментов языковой модели, которая пишет новый ответ | Да | LLM может галлюцинировать; ответ надо проверять по источникам |

Наш помощник реализует **Retrieval** и выдаёт точные выдержки. Он не
называет это генерацией, пока не подключена языковая модель. В
факультативном режиме `--neural` можно сравнить нейросетевой поиск с
TF-IDF, а в `--llm` — попробовать локальную LLM и проверить, не
придумала ли она факты.

## 8. Ограничения

- База знаний небольшая и учебная: 17 документов.
- TF-IDF не понимает синонимы без общих слов; это не нейросетевой поиск.
- Ответ собирается из цитат, а не генерируется языковой моделью.
- Порог сходства нужно настраивать на своих вопросах.
- Семантический поиск и локальная LLM — факультатив и требуют ресурсов.
- Найденная цитата не заменяет проверку прав доступа и содержания.

## 9. Как запустить

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Дополнительные режимы:

```bash
python main.py --ask
python main.py --question "Что показывает precision?"
python main.py --neural
python main.py --llm
```
